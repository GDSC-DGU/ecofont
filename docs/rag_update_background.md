초기 RAG 활용 방안 검토
기존에는 다음 두 가지 목적으로 RAG를 활용할 수 있을 것 같아 도입을 검토하였습니다.

방법 1) 최적화 초기 세팅(Parameter Reference): 사용자가 업로드한 폰트와 유사한 외곽선(Outline) 데이터를 검색하여, 가독성을 유지할 수 있는 최적의 타공 크기와 간격 등 엔진의 초기 파라미터를 도출하는 용도.
방법 1을 사용할 때는 (원본 폰트, 변환된 에코폰트) 쌍의 데이터셋이 필요합니다. 원본 폰트 데이터셋을 업로드한 폰트와 비교하여 유사한 원본 폰트를 찾고, 해당 원본 폰트의 에코폰트를 활용합니다

로직 flow example

사용자가 폰트 A를 올린다.
DB에서 A와 가장 유사한(예: 두께, 장평이 비슷한) 폰트 B를 찾는다.
B에 적용되었던 "구멍 크기 0.2mm, 간격 0.5mm"라는 숫자 값을 그대로 가져와서 A에 적용한다.
방법 2) 디자인 스타일 전이(Style Generation): 소수 민족 언어와 같이 데이터가 부족한 경우, 기하학적 특징이 유사한 타 문화권의 폰트 디자인을 참고하여 해당 언어에 적합한 새로운 에코폰트 외곽선을 생성하는 용도.
방법 2를 사용할 때는 사용자가 입력한 폰트 언어와 구조적으로 유사한 언어를 찾아야 하기 때문에 다양 한 일반 폰트 데이터셋이 필요합니다(에코 폰트는 DB에 저장하지 않아도 됨)

로직 flow example

디자인 특징 학습: AI가 수만 개의 폰트를 공부해서 '날카로운 끝처리', '획의 굵기 차이' 같은 디자인 요소들을 숫자로 변환하는 법을 익힙니다.

뼈대 기반 검색: 새로운 글자에서 디자인을 다 빼고 남은 '뼈대'를 분석합니다. 그다지 닮지 않은 글자라도 뼈대 구조가 가장 비슷한 기존 폰트 속의 글자를 찾아냅니다.

부품 단위 매칭: 두 글자를 '직선', '동그라미' 같은 작은 부품 단위로 쪼갭니다. 그다음 "새 글자의 이 곡선은 기존 글자의 이 동그라미 부분과 대응된다"라고 일일이 연결합니다.

새로운 외곽선 그리기: 새 글자의 뼈대 위에 기존 글자의 디자인(스타일)을 입힙니다. 마지막으로 폰트 파일로 쓸 수 있게 외곽선 좌표를 새로 계산해서 다시 그려냅니다.

제외 사유
기술적 선후 관계 및 데이터 의존성 (방법 1을 사용할 경우)
사유: 지식 참조형 RAG를 구현하려면 [일반 폰트 - 에코 폰트]의 페어(Pair) 데이터셋이 선행되어야 합니다.

이러한 데이터셋을 만들기 위해서는 에코 폰트 생성 모델의 개발이 선행되어야 하기 때문에 Rag 작업을 개발 초기에 할 수 없고, 또 생성 모델의 성능에 따라 rag의 효과가 결정되는 점을 고려하여 mvp에서 rag를 제외하고 생성 모델 최적화에 모든 리소스를 집중하기로 했습니다.

모델 학습 시간 및 인프라 비용 (방법 2를 사용할 경우)
사유: 형태 전이를 통한 외곽선 재설계 로직은 방대한 폰트 데이터에 대한 구조적 학습이 필요하며, 이는 MVP 개발 기간 내에 완결 짓기에는 학습 시간이 너무 오래 걸릴 것으로 예상됩니다. 따라서, 한정된 일정 내에 모델의 정확도를 보장하기 어려운 고난도 모델링보다는, 실질적인 가독성과 잉크 절감 수치를 증명할 수 있는 알고리즘 고도화가 더 시급하다고 판단했습니다.

기획의 본질적 목표 집중
본 프로젝트의 주 목적은 '세상의 모든 폰트를 가독성 있게 에코폰트로 변환'하는 것인데, 부가적인 스타일 전이 기능은 서비스의 '확장성'에는 도움이 되나, '에코폰트 생성'이라는 본연의 가치를 증명하는 데 필수적인 요소는 아닙니다. 따라서 다른 부분에 힘을 쓰기로 결정했습니다.

향후 추가 가능성 (Post-MVP Roadmap)
그러나 이러한 RAG방식 자체는 구현이 된다면 매력적인 기능으로 생각되어, 엔진 안정화 이후 축적된 변환 데이터를 활용하여 지식 참조형 RAG를 도입하고, 소수 민족 언어 지원을 위한 스타일 전이 모델을 모듈 형태로 추가할 수 있도록 확장성을 고려한 설계를 유지합니다.
