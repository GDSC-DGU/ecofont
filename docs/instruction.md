## 1. 기본 규칙

### 탐색과 수정을 구분하기

질문이 바로 문서 수정으로 이어지지 않게 한다. 탐색할 때는 아래 패턴을 사용한다.

```text
문서는 수정하지 마. [이 결정]이 왜 이렇게 된 건지 설명해줘.
```

```text
아무것도 바꾸지 마. [이 변경]의 영향을 먼저 평가해줘.
결정하기 전에 결과를 이해하고 싶어.
```

답변에 만족했을 때만 수정 지시를 내린다.

---

### 질문 → 문서 → 승인 흐름

AI가 불명확한 사항이 있으면 마크다운 파일에 질문을 작성하고 멈춘다. 파일을 열어 답변을 채운 뒤, AI에게 다시 읽고 진행하라고 지시한다.

```text
질문에 답변했어. 파일 다시 읽고 계속 진행해줘.
```

각 단계가 끝나면 결과물을 검토한 후 **변경 요청** 또는 **승인 후 진행** 중 하나를 선택한다.

---

### 컨텍스트 관리

자연스러운 결정 시점(질문 파일 작성, 문서 승인)마다 컨텍스트를 초기화한다. AI의 현재 작업은 이미 파일에 저장되어 있으므로 초기화해도 작업이 사라지지 않는다.

재개 시 사용할 패턴:

```text
이전에 중단된 작업을 재개해. 마지막으로 한 작업은 [내용]이야.
[다음 액션]부터 계속 진행해줘.
```

---

### 프롬프트 묶기 원칙

- **같은 주제의 변경** → 하나의 프롬프트에 묶기
- **관련 없는 변경** → 하나씩 분리해서 진행

## 3. Inception 단계 (기획)

현재 이 단계에 있다.

### 완료 기준

- [ ] `vision_document.md` 전체 섹션 검토 및 확정
- [ ] `tech_stack.md` 미결정 사항 결정
- [ ] `technical_environment.md` 작성 (언어, 프레임워크, 금지 라이브러리, 코드 예시 포함)

### technical_environment.md에 반드시 포함할 내용

```text
- 언어 및 버전 (예: Python 3.11, Node.js 20)
- 패키지 매니저
- 웹 프레임워크
- 클라우드 및 배포 방식
- 테스트 프레임워크
- 금지 라이브러리 (이유 + 대체 라이브러리 포함)
- 엔드포인트, 함수, 테스트 코드 예시 각 1개 이상
```

> 금지 라이브러리는 이유와 대체 라이브러리를 함께 명시해야 AI가 올바른 대체 결정을 내릴 수 있다.

### Inception 진행 방법

```text
vision_document.md와 tech_stack.md를 읽고 요구사항 분석을 시작해줘.
```

## 4. Construction 단계 (구현)

Inception이 완료된 후 진행한다.

### 설계 → 코드 순서

각 구현 유닛은 아래 순서를 따른다:

1. **Functional Design** — 비즈니스 로직, 데이터 모델
2. **NFR Design** — 성능, 보안, 기술 스택 적용
3. **Code Generation Plan** — 생성할 파일 목록 검토
4. **Code Generation** — 실제 코드 생성
5. **Build & Test** — 빌드 및 테스트 검증

### 코드 생성 전 반드시 확인할 것

코드 생성 계획(Plan)을 승인하기 전에 확인:
- 파일 경로가 올바른가 (aidlc-docs/ 안에 코드가 생성되지 않는가)
- 설계 문서에서 명세한 모든 항목이 포함되어 있는가

### 설계 변경 시 패턴

```text
아무것도 바꾸지 마. [X] 이슈를 발견했어. 설계에서 어디를 수정해야 하는지 파악해줘.
```

```text
[특정 설계 문서]를 [수정 내용]으로 업데이트해줘.
그리고 요구사항이나 유저 스토리에도 영향이 있는지 확인해줘.
```

```text
[유닛 이름]의 설계가 업데이트됐어. 영향받는 파일만 코드 재생성해줘.
```

## 5. 절대 하지 말 것

### 코드 파일 직접 수정 금지

생성된 코드 파일을 직접 편집하면 설계 문서와 코드 간 불일치가 발생한다. AI가 이후 작업에서 잘못된 설계를 참조하게 된다.

**올바른 방법:**

1. 문제를 AI에게 설명 (파일 수정 없이)
2. 설계 문서 먼저 수정
3. 수정된 설계를 기반으로 코드 재생성

**불가피하게 직접 수정했을 경우:**

```text
[파일]을 팀 블로킹 해소를 위해 직접 수정했어.
수정 내용은 [설명]이야. [설계 문서]를 이 내용으로 업데이트하고
다른 문서와 불일치가 없는지 확인해줘.
```

### 탐색과 수정 혼용 금지

"그냥 한번 해봐"는 없다. 탐색은 "문서 수정하지 마"로 시작하고, 결정이 나면 명시적으로 수정을 지시한다.
